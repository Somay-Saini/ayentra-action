Why Unit Tests Are Not Enough

Three Production Bugs Normal Tests Miss

Unit tests only check the examples you thought of writing. Ayentra tests thousands of edge cases and thread timings automatically before code reaches production.

⚡

Multi-Thread Race Conditions

Normal tests run one request at a time and pass. In production, two requests arriving together can corrupt balances or double-book tasks. Ayentra tests parallel thread timings to catch races early.

# Tests parallel thread timings automatically @invariant(..., check_concurrency=True) # Catches race conditions before production
🔍

Unexpected Edge-Case Inputs

Developers usually test clean positive numbers and normal strings. Ayentra feeds negative amounts, NaN floats, and empty strings, then shrinks any crash down to a 2-line example.

# Shrunk to a 2-line reproduction: ledger.reserve(units=-1) # Available becomes 101, Reserved becomes -1
🛡️

Fixes That Break Something Else

A quick hotfix often solves one crash while breaking another feature. Ayentra tests every suggested code fix inside an isolated sandbox against your full test suite first.

# 3-step sandbox check before saving: 1. Re-run failing input (PASS) 2. Test 120 random edge cases (PASS) 3. Run your full pytest suite (PASS)
How It Works

From Rule to Verified Fix in 4 Steps

You write the rule once. Ayentra handles the edge-case testing, bug shrinking, and sandbox verification automatically.

Step 01

Write One Rule

Add an @invariant decorator in Python or a rule in ayentra.toml stating what must always stay true.

Step 02

Auto-Generate Inputs

Ayentra reads your Python type hints (ints, Decimals, dates, dataclasses) and generates realistic edge-case inputs automatically.

Step 03

Shrink to 2 Lines

When an input breaks your rule, Ayentra simplifies it down to the smallest 2-line reproduction so you see the exact cause immediately.

Step 04

Verify Fix in Sandbox

Ayentra generates a clean code patch and tests it in a temporary sandbox against both the bug and your existing pytest suite.

Fast Setup

Add to Your Pipeline in 60 Seconds

Drop Ayentra into GitHub Actions, configure with pyproject.toml, or run it locally in your terminal with one command.

.github/workflows/ayentra.yml 
# .github/workflows/ayentra.yml
name: Invariant Verification Gate
on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

jobs:
  verify:
    name: Run Invariant Verification
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.11'

      - name: Ayentra Invariant Gate
        uses: ayentra/ayentra-action@v0.1.0
        with:
          target: src/
          fix: true
          sarif-output: ayentra.sarif

      - name: Upload SARIF Report
        uses: github/codeql-action/upload-sarif@v3
        if: always()
        with:
          sarif_file: ayentra.sarif
pyproject.toml 
# pyproject.toml
[tool.ayentra]
target = "src/"
max_examples = 120
check_concurrency = true
sandbox_timeout = 30
sarif_output = "ayentra.sarif"
fail_on_violation = true
deterministic_receipt = true
